Report Builder

Build, filter, and export custom reports from any Odoo model — no coding required.

Overview

Report Builder lets you create downloadable reports from any data model in Odoo without writing code. Choose the source data, pick the fields you want as columns, apply optional filters, and download the result as Excel, CSV, a cross-tab Matrix spreadsheet, or a formatted PDF.

Reports can also be pinned into any Odoo app menu so that team members can trigger a download directly from their usual workflow — no visit to the Report Builder settings page required.

What you can do

  • Report on any non-temporary Odoo model (sales orders, products, contacts, stock moves, custom models, etc.).
  • Include fields from related records using dot-notation paths — e.g. the customer's country on a sales order.
  • Apply domain filters to limit rows using Odoo's standard filter builder.
  • Export as Excel, CSV, Matrix, or PDF.
  • Place a one-click download link under any menu in any app.

Finding Report Builder

Report Builder appears as its own top-level application in the Odoo home screen. Click the Report Builder app icon to open the reports list. All reports you have created are shown here, along with a column count and the output format for quick reference.

Access rights You must be an Odoo administrator or a member of the Report Builder access group to create and edit reports. Other users can only run reports that have been placed in their app menus.

Quick-Start Checklist

To produce your first report in under five minutes, follow these steps:

  1. Open the Report Builder app and click New.
  2. Enter a Report Name.
  3. Select the Primary Model (the data source — e.g. Sales Order).
  4. Choose a Report Format (Excel is the default).
  5. Open the Columns tab and add at least one column using the field selector.
  6. Click Save, then click the Run Report button to download.

Creating a Report

From the reports list, click New in the top-left corner. The report form opens with several sections. Fill in the Report Configuration section first — the rest of the form depends on the model and format you choose.

Click Save manually (the floppy-disk icon) or navigate away to auto-save when you are done. Changes to the report name or menu placements are applied immediately on save.

Report Configuration

The Report Configuration section at the top of the form defines the fundamental settings for the report.

Field Purpose
Report Name ✱ The name shown in the report list, in exported file names, and on the first row of Excel / PDF outputs. Keep it short but descriptive — e.g. Open Sales Orders — This Week.
Description Free-text notes about what the report covers, who it is for, and when to run it. Shown on the form only — not included in the export.
Primary Model ✱ The Odoo model whose records form the rows of the report. Start typing to search by model label (e.g. Sale Order) or technical name (e.g. sale.order). The model drives the field selector in the Columns tab and the domain filter builder.
Report Format ✱ One of Excel (.xlsx), CSV, Matrix, or PDF. Selecting Matrix or PDF reveals additional configuration options below. See the Output Formats section for details on each.
Active Un-tick to archive the report. Archived reports are hidden from the list but can be restored via the Archived filter. Any menu entries created by the report are also hidden while the report is archived.
Primary Model is permanent Changing the Primary Model after adding columns will invalidate all existing column field paths. It is best to decide on the model before building the column list.

Columns Tab

Open the Columns tab to define what data appears in each column of the report. Columns appear in the order set by their drag handle (sequence). You must select a Primary Model before columns become available.

Using the Field Selector

Click the field selector in the Field Path cell to open an interactive browser for all fields on the Primary Model. Click a field name to select it. The Column Header is auto-populated from the field's label — you can overwrite it at any time.

Including Related Fields

For relation fields (Many2one, Many2many, etc.) a › arrow appears next to the field name in the selector. Click it to traverse into the related model and pick a field there. This builds a dot-notation path automatically, e.g.: 

partner_id.country_id.name
order_line.product_id.categ_id.name
user_id.email

The report engine follows the chain at export time, so nested related fields work without any extra configuration.

Tip — Many2many fields When a field path traverses a Many2many or One2many relation, the report engine joins all related records into a single comma-separated value in that cell. This is usually the most useful behaviour for list exports.

Ordering Columns

Drag the ⠿ handle on the left of each row to reorder columns. The sequence number updates automatically. The order in the list is the order in the exported file — left to right for Excel/CSV/Matrix, and left to right in the PDF table.

Column Fields Reference

FieldDescription
Field Path ✱ Dot-notation path to the field, built interactively by the field selector. Examples: name, partner_id.name, order_line.price_subtotal.
Column Header The label for this column. Auto-filled from the field's display name when you select a field. Leave blank to fall back to the raw field path.
Width (chars) Suggested column width for Excel output, measured in character widths. 0 (the default) lets the engine auto-size based on the longest value, up to a maximum of 60 characters.

Filter Conditions

The Filter Conditions section lets you restrict which records appear in the report using Odoo's standard domain builder. An empty filter ([]) means all records from the Primary Model are included.

Using the domain builder

  1. Click Add a filter in the domain widget.
  2. Click the first dropdown to choose a field.
  3. Choose a comparison operator (is equal to, contains, is set, etc.).
  4. Enter or select the value to compare against.
  5. Add further conditions with AND / OR as required.

Domain Description

The Domain Description text field below the domain builder accepts a free-text summary of what the filter does, for example "Confirmed orders created this financial year". This text is printed in the report header row of Excel and PDF exports so recipients understand what data they are looking at.

If this field is left blank, the raw domain expression is printed in the header instead.

Performance note Very broad reports with no filter (or a filter that matches thousands of records) may take several seconds to generate. Consider adding a date range filter to keep the result set manageable.

Menu Placement

The Menu Placement tab lets you pin a one-click download link for this report under any number of Odoo app menus. This is how you expose a report to end-users without requiring them to open the Report Builder app.

How it works

  1. Open the Menu Placement tab.
  2. Click the Add to Menus tag input and search for a parent menu — e.g. Reporting under the Sales app.
  3. Select as many parent menus as needed. You can also type a new name to create a fresh menu entry on the fly.
  4. Save the report.

On save, Report Builder automatically creates a child menu item named after the report under each selected parent. Clicking that menu item anywhere in Odoo triggers an immediate download of the report. If you change the report name or adjust the menu list later, the menu entries are rebuilt automatically.

Refreshing menus Newly created menu entries appear after the next browser page reload. If you do not see the menu item immediately, press F5 or hard-refresh the page.

Output Formats

Excel

.xlsx

Formatted spreadsheet with styled headers, banded rows, frozen pane, and auto-column widths. Best for data analysis and sharing with stakeholders.

CSV

.csv

Plain comma-separated values. Ideal for importing into other systems, Power BI, or any tool that accepts raw tabular data.

Matrix

.xlsx

Cross-tab spreadsheet with row values on the left, column values across the top, and a single field value at each intersection. Great for pivot-style views.

PDF

.pdf

Print-ready document with a title block and formatted table. Configurable page size (A4–A0) and portrait/landscape orientation.

Excel (.xlsx)

The Excel export produces a fully formatted .xlsx workbook with one sheet named after the report. The sheet layout is:

  • Row 1 — Report name (dark blue, bold, 14 pt).
  • Row 2 — Primary model name.
  • Row 3 — Domain description (or raw filter expression).
  • Row 4 — Total record count.
  • Row 5 — Blank separator (narrow).
  • Row 6 — Column headers (white text on navy background).
  • Rows 7+ — Data rows with alternating white / pale-blue bands.

The top six rows (meta + header) are frozen so they remain visible when scrolling large datasets. Column widths are automatically sized to the widest value in each column, up to a maximum of 60 characters.

No extra configuration is required beyond the base Report Configuration and Columns tabs.

CSV

The CSV export writes a header row followed by one data row per record. All values are quoted. The file is encoded in UTF-8 with BOM so that Microsoft Excel opens it correctly without a text-import wizard.

CSV output is purely data — there are no title rows or formatting. Use this format when the file needs to be consumed programmatically or imported into another application.

Matrix

A matrix report is a cross-tab (pivot-style) Excel spreadsheet. You define three fields from the Primary Model:

SettingDescription
Row Axis Field ✱ The field whose distinct values become the rows of the matrix. Must be a Many2one, Char, or Selection field.
Row Axis Label Custom heading for the row axis. Defaults to the field's display name if left blank.
Column Axis Field ✱ The field whose distinct values become the columns of the matrix. Must be a Many2one, Char, or Selection field.
Column Axis Label Custom heading for the column axis.
Cell Value Field ✱ The field displayed at the intersection of each row/column combination. Any field type is accepted.

Row and column values are automatically sorted alphabetically. Where there is no record matching a particular row/column pair, the cell is left blank. Each row group alternates between white and pale-blue backgrounds. The first row (meta) and column (row labels) are frozen.

One value per intersection If multiple records share the same row/column pair, the matrix stores the value from the last matching record encountered. Matrix format is designed for data where each row-column combination is unique or where only the most recent value matters.

PDF

The PDF export generates a ReportLab-rendered document suitable for printing or sharing as a read-only report. Two extra settings become visible when PDF is selected:

SettingOptionsDefault
Page Size A4, A3, A2, A1, A0 A4
Orientation Portrait, Landscape Portrait

Column widths in the PDF are divided equally across the usable page width. For reports with many columns, choose Landscape or a larger page size to avoid cramped text. The column header row repeats at the top of each page.

Downloading a Report

From the report form

Open the report in Report Builder and click the Run Report button in the top header bar. The browser will immediately download the file in the configured format. There is no preview — the file downloads directly.

From an app menu

If the report has been placed under one or more app menus (see Menu Placement), any authorised user can trigger the download by clicking that menu item. The report runs with the logged-in user's access rights, so only records that user is permitted to read will appear in the output.

FAQ & Tips

Why does my report show no records even though data exists?

Check the Filter Conditions section. If a filter is applied, it may be too restrictive. Remove or relax the filter to test with all records, then refine it. Also confirm that the logged-in user has read access to the records in question — the report respects Odoo access rules.

Why is a related field showing as blank?

A blank value in a related-field column means either the relation is not set on that record, or one of the intermediate relations in the path is empty. For example, partner_id.country_id.name is blank if the partner has no country set. This is expected behaviour.

Can I report across multiple models?

Each report has a single Primary Model, but you can traverse into related models as many levels deep as needed using the dot-notation field path. For genuinely multi-model data that cannot be reached through a relation, create separate reports — one per model — or ask your developer to create a computed field or SQL view that joins the data.

Why does my matrix have duplicate or missing cells?

The matrix engine stores one value per (row, column) pair — the last record processed for that pair. If you have multiple records with the same row and column values, only one cell value is kept. Use a domain filter to ensure each row-column combination appears at most once, or choose a different cell value field (such as a sum or count computed field) that aggregates the values upstream.

Can I schedule a report to run automatically?

Report Builder does not currently include an automated scheduler. Reports are generated on-demand either by clicking Run Report in the form view or by clicking the menu shortcut placed in an app menu.

The menu item does not appear after I save the report.

Menu items are created immediately on save, but the browser-side menu cache must be refreshed. Hard-refresh the page (Ctrl+Shift+R on Windows/Linux, Cmd+Shift+R on macOS) or simply navigate away and back.

How do I delete a report cleanly?

Open the report and use Action → Delete. Report Builder automatically removes the associated menu entries and download action when a report is deleted. Alternatively, archive the report (set Active to off) to hide it without permanently deleting it.

What data types are supported in columns?

All Odoo field types can be included as columns. Values are converted to strings for export:

  • Boolean fields — displayed as Yes or No.
  • Many2one / relation fields — the record's display name is used.
  • Many2many / One2many — all related record names are joined with a comma.
  • Date / Datetime — formatted as a string using the field's standard representation.
  • All other types — converted to string via Python's str().
